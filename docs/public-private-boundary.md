# Public and private boundary

The public repository may contain generic lifecycle schemas, fictional
examples, storage code, projection infrastructure, and documentation.

A private integration owns:

- real names and entity identifiers;
- domain event schemas and role rules;
- source reports and approval statements;
- local database and backup locations;
- agent task or session references;
- vault, journal, CRM, or application paths;
- workflows that decide when a proposal has human approval.

No private integration file is required to run the public fictional example.
